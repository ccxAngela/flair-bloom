# 组合键触发与连发评估

Status: draft
Goal: 支持组合键触发与组合键输出，例如 `Ctrl+F → Shift+1`，保留现有单键规则、长按／切换模式与停止能力。

## 1. 背景与已有能力

用户已明确要求触发和输出两侧都支持组合键。本文件是评估草案，产品代码未实现。

| 能力 | 已有基础 | 需要补齐 |
| --- | --- | --- |
| 规则与配置 | `BurstRule` 有触发、输出、独立停止键；支持导入导出与净化 | 三个槽位目前都是单个 `KeyId`，组合键表达与兼容保护 |
| 输入监听 | 引擎记录按住集合，过滤重复按下 | 按组合匹配、释放任一成员停止 Hold、组合冲突判定 |
| 连发调度 | 目标键所有者表、成功注入账本、停止同步与异常清理 | 修饰键生命周期、多规则输出协调、部分成功后的补偿 |
| 界面 | 共用录键框、竖版规则卡、横版键鼠图、浮窗 | 等待主键再完成录入、多键显示、横版编辑入口与长度适配 |
| 输出通道 | SendInput、Interception、DD、外设模式已有按键发送接口 | 验证修饰键映射、回灌、事件吞吐与停止边界 |

输出已由 `BurstRule.steps` 统一表达，步骤使用单个 `KeyId`；组合绑定尚未实现，本草案不构成队列任务的前置依赖。

关联的[统一输出队列实施记录](archive/output-sequences.md)已将单键正规化为一步队列，保留长按／切换触发。组合键负责一个步骤的成员绑定，队列负责步骤先后；实施时复用现有队列、配置兼容方案和释放账本，避免另建一套宏模型。当前工期不包含已发布的队列播放器与录制。

## 2. 已定与建议

- **D1（用户确认）**：触发与输出均支持组合键。
- **D2（本次工作范围）**：只评估、拆任务和估工期；路线图保持 draft。

以下为建议，尚未作为用户已批准的产品规则：

- **P1 范围**：先支持 `Ctrl / Shift / Alt` 中的一个或多个修饰键加一个普通键盘主键；继续支持既有单键鼠标规则。Win 组合、鼠标组合、任意 `A+B` 和有先后时序的宏另行评估。规则的独立停止槽也应接受组合键，全局紧急停止保留独立单键入口。
- **P2 触发**：主键按下时匹配，优先匹配修饰键集合一致的组合规则；未命中时按旧单键行为处理。同一按键的自动重复不反复切换；先按主键再补修饰键不追溯启动。Hold 在任一必需成员松开时停止。左右修饰键建议第一期按类别匹配，输出使用固定侧；AltGr 与左右双按需要明确排除或验证。
- **P3 冲突**：`F` 与 `Ctrl+F` 同时配置时，按下 `Ctrl+F` 只启动组合规则；仍沿用同一触发上的多规则及互斥组语义。`Ctrl+Shift+F` 是否回退单键 F，需在交互样例里明确；不能暗中改变旧配置在修饰键按住时的行为。
- **P4 输出**：每拍按下修饰键、点按主键、释放主键、逆序释放本拍取得的修饰键。通过调度状态机协调本应用中修饰键集合不兼容的规则，禁止在 Ctrl 输出尚未释放时插入另一条普通 `2`。不能简单把修饰键包在现有 Down / Up 相位外面，也不能阻塞停止命令等待整拍。
- **P5 后端**：四种模式列入验证目标；DD／外设下触发、停止与输出存在成员重叠时，按实际来源识别能力决定支持范围。不能只比较主键，也不能未经验证就承诺 `Ctrl+F → Ctrl+1` 在 DD 下可靠。独立紧急停止键建议禁止出现在输出成员中。
- **P6 横版**：单键快速编辑继续可用，组合规则显示完整标签并提供明确的详细编辑入口；点击主键不能悄悄覆盖组合规则。
- **P7 物理修饰键**：必须说明触发后仍按住的真实修饰键会参与实际输出。例如 Hold 模式按住 `Ctrl+F` 连发 `Shift+1`，目标可能读到 `Ctrl+Shift+1`。建议先沿用系统实际键状态，不擅自抬起用户按住的 Ctrl；若要求输出严格独立于触发修饰键，需要另外评估物理事件拦截、延后起拍或限制不兼容的 Hold 绑定。此时不能仅靠调度器内的所有者表解决。

这些细节不阻塞继续做数据与引擎设计，但实现验收前需确定范围和匹配表。

## 3. 问题清单

下表严重度指“扩展为组合键时必须解决的问题”，不代表现有单键功能均已故障。

| # | 问题 | 严重度 | 位置 | 任务 |
| --- | --- | --- | --- | --- |
| I1 | 不同规则分相位输出，修饰键会改变其他规则的普通键；仅增加引用计数不足以隔离 | P0 | `packages/burst-engine/src/scheduler.rs:495` | T4 |
| I2 | 停止只释放单个目标，兜底清理无主键／修饰键顺序；组合中途失败可能留下修饰键 | P0 | `packages/burst-engine/src/scheduler.rs:451`、`:653`、`:699` | T4 |
| I3 | 只追加默认修饰键字段，旧版可能忽略它，把 `Ctrl+1` 静默执行成 `1` | P0 | `packages/qzh-profile/src/profile.rs:103`、`packages/qzh-profile/src/lib.rs:40` | T2 |
| I4 | 按单键建立触发／释放索引，不能处理任意组合成员松开与更具体的触发规则 | P1 | `packages/burst-engine/src/rules.rs:7`、`packages/burst-engine/src/lib.rs:322` | T3 |
| I5 | 当前槽位明确拒绝规则修饰键；DD 回灌过滤依赖 50ms 队列，组合成员扩大歧义 | P1 | `packages/qzh-profile/src/key_policy.rs:108`、`packages/win-input/src/lib.rs:82` | T1、T3、T6 |
| I6 | 录键和 DTO 都只接收单键；浮窗只展示触发键，组合长标签增加尺寸压力 | P1 | `apps/main/src/windows/panel/components/KeyCapture.tsx:336`、`apps/main/src/windows/panel/PanelApp.tsx:284`、`apps/main/src/windows/float/FloatApp.tsx:37` | T2、T5 |
| I7 | 现有限速按规则数量计算，组合每拍至少四个事件，原来的吞吐预算不再等价 | P1 | `packages/burst-engine/src/scheduler.rs:495`、`packages/win-input/src/lib.rs:674` | T4、T6 |

SendInput 的一次数组调用有连续插入保证，但当前统一接口逐事件发送；DD／外设也不能直接获得这一保证。系统已按住的键还会影响注入，因此本应用可以协调自身规则，不能承诺隔离用户或其他进程的真实修饰键。[Microsoft SendInput 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)

源码参照 TheCelestialDiviner 1.9.1 已支持输出修饰键，但采用各任务线程按下／释放的方式，不能据此推定它已解决跨规则修饰键干扰；同键 DD 的约束见 [输入通道与共存边界](../../skills/flair-bloom/references/engineering/architecture.md#输入模式与注入通道)。

## 4. 建议任务卡（均未开始）

### T1 · 语义与输入能力表

- **Fixes:** I5。
- **Change:** 明确修饰键规范化、触发优先级、独立停止、输出共享与物理键重叠策略；梳理四后端成员重叠能力。
- **Acceptance:** `F / Ctrl+F / Ctrl+Shift+F`、主键先按、左右双按、全局停止均有唯一预期。
- **Test:** 形成后续自动化使用的行为样例；DD 标记与来源识别先做小探针验证。
- **Rollback:** 草案调整，不写用户配置。
- **Depends on:** 无。

### T2 · 数据模型与配置兼容

- **Fixes:** I3、I6。
- **Change:** 引入共用按键绑定类型，贯通 Rust／前端 DTO、导入导出、复制和配置净化。确定新旧读取策略，再决定具体存储形状。
- **Acceptance:** 旧单键配置无损读取；新版组合保存再读仍是原组合；旧版遇到新组合必须拒绝或安全禁用，不能执行成裸主键。
- **Test:** 旧配置、缺省字段、非法成员、导入导出往返；用旧版读取器验证新配置的失败方式。
- **Rollback:** 保存前备份；优先向前修复并保留新数据。不得仅裸 bump `CURRENT_SCHEMA_VERSION`，也不得靠删修饰键降级。
- **Depends on:** T1。

### T3 · 组合触发与停止

- **Fixes:** I4、I5。
- **Change:** 扩展触发与成员释放索引，按主键按下沿匹配；统一规则槽位校验与运行时后端约束。
- **Acceptance:** Hold 任一成员松开即停；Toggle 每次有效按下只切换一次；全局停止、组内替换和长按插队保持预期。
- **Test:** 输入事件序列覆盖组合重叠、自动重复、丢失释放、模式切换及自注入回灌。
- **Rollback:** 关闭组合启动并保留配置内容，继续支持单键。
- **Depends on:** T1、T2。

### T4 · 组合输出调度与释放

- **Fixes:** I1、I2、I7。
- **Change:** 让主键与修饰键参与可中断的拍内状态机、所有者账本及有序释放；按实际事件成本限速，补偿部分注入失败。
- **Acceptance:** 本应用普通 `2` 不串成另一规则的 `Ctrl+2`；多个组合能公平运行；暂停、停止、切配置、切后端、异常退出路径都有确定的释放顺序。
- **Test:** 调度器确定性仿真和失败注入，覆盖每个发送阶段失败、停止抢占与共享成员；真机验证作为 T6。
- **Rollback:** 运行时禁用组合输出并清理已发送成员，保留新版读取器与配置。
- **Depends on:** T2。

### T5 · 录键、展示与说明

- **Fixes:** I6。
- **Change:** 录键等待主键、展示完整组合，更新规则卡、冲突提示、横版、浮窗与语音；同步 manual、对应教程、工程文档和 CHANGELOG。
- **Acceptance:** 可建立并保存 `Ctrl+F → Shift+1`；横版不会丢失组合；长标签在缩放和双屏下可读。
- **Test:** 录入／取消／切焦点交互，单键回归，双屏不同 DPI 和应用缩放检查。
- **Rollback:** 隐藏组合编辑入口但保留完整展示与数据。
- **Depends on:** T2、T3、T4。

### T6 · 四后端验证与性能收口

- **Fixes:** I5、I7。
- **Change:** 在测试配置与输入接收器中测按键序列、回灌延迟、有效频率和停止；按通道记录支持与限制。
- **Acceptance:** 各通道明确可用范围；未验证或不可靠的成员重叠明确限制；停止后没有持续注入，账本和接收器状态可核对。
- **Test:** SendInput、Interception、DD、外设逐项验证；单条／并发组合、单键混用、物理修饰键按住、后端切换；DD 有无 Interception 过滤驱动的环境需分开记录。
- **Rollback:** 能力开关禁用失败通道的组合功能，不自动卸载系统驱动。
- **Depends on:** T3、T4、T5。

## 6. 风险与边界

- 支持组合键和放开 DD 同键 Toggle 是两件事。来源判别没有验证前，不能因竞品支持就删除现有限制。
- 若要求任意左右键组合、鼠标组合、Win 系统快捷键，或所有后端都允许任意重叠，需重新估算。
- 工期不包含将输出与用户真实按住的修饰键完全隔离；如将其作为组合键必需语义，应先调整 P7 和验收范围，再估算。
- 新配置一旦持久化，直接回退旧应用存在解释错误风险。兼容方案须先于界面开放，回滚以向前修复／禁用能力为主。
- 不承诺不同游戏均接受相同按压时长与连发速度；驱动升级、蓝屏处理、第三方驱动卸载不并入本功能。
