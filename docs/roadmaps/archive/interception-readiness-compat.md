# 游戏模式就绪检测兼容与诊断

Status: completed

## 范围与判定

用户要求修复老用户环境误报并增加诊断，随后明确询问能否区分刚好 10 槽与槽位耗尽。就绪指驱动通道可初始化且存在后端所需的可读键盘，不等于游戏已经接收输入。

- SDK 合法键盘槽为 1–10、鼠标槽为 11–20；恰好占满 10 槽不代表现有设备失效。
- 满槽与 Windows 类设备编号偏高只作诊断提示；SDK 无法暴露第 11 个键盘，因此计数不能区分刚好满槽与额外设备缺槽，报告明确标注额外设备状态未确认。
- 类编号采集失败不覆盖实际 SDK 读到的可用设备；鼠标缺失保留键盘通道，鼠标注入可能回退通用模式。
- 通道打不开或没有可读键盘仍阻止启用；需要管理员权限时先处理提权。
- 临时回退只更换运行通道，保留保存的输入模式；手动选择及卸载／修复的持久化语义保持原有契约。

## 实现

就绪纯判定位于 `packages/win-input/src/interception_health.rs`，纳入共享 crate 的常规 CI。应用状态和诊断复用同一判定，风险单列为不阻止启用的提示。

诊断报告记录当前／保存模式、服务状态、SDK 通道状态、可读槽号、Windows 类设备编号、允许／阻止及其原因；阻止时记录当时的应用日志。独立诊断脚本采集类设备编号及保存模式，并收录 Interception 就绪相关日志。未就绪弹窗提供打开诊断入口。

## 验证与交接

- 就绪判定 8 项单测通过，覆盖双方各恰好 10 槽、合法最后一槽、高 Windows 编号、键盘单独可用、类编号读取失败、服务记录缺失但通道可读，以及真正没有通道／键盘。
- `win-input` 库测试 46 项通过、2 项真实环境测试忽略，其中就绪判定 8 项通过。
- Tauri 状态层 7 项单测通过；全目标全特性 Clippy、Rust 格式检查通过。
- 前端 lint、格式、类型、84 项测试、生产构建和文档一致性通过。
- 独立诊断脚本解析及只读报告导出通过，报告包含 KeyboardClass、PointerClass 与 Interception 依据。

本机只读探测为键盘 4 个、鼠标 2 个，当前不满足误拦条件。边界由合成场景复现，未主动制造真实设备槽耗尽，也未发送测试按键。未执行发版、版本或 schema 升级；用户原有应用进程与配置未改动。
