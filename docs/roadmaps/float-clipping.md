## 已有证据

- 用户录屏约 1.96–2.00 秒出现完整的是放大前的小内容，随后内容放大并裁切；尚未与原生窗口事件时间戳对齐。
- `FloatApp.tsx` 的尺寸路径是内容测量 × 应用 zoom → `LogicalSize`，主要由内容 `ResizeObserver` 和面板缩放广播触发；与主面板按实际窗口适配内容的路径不同。
- 独立浏览器中，空态浮窗内容固有尺寸为 159×42 CSS 像素，不随测试 DPR 改变；这不等同于 Windows 原生窗口验证。
- 本机 Windows 11 Enterprise Evaluation 26H2，构建 26300.9457，WebView2 156.0.4314.56，应用 0.7.0。100% 系统缩放下读取隐藏浮窗，原生窗口、WebView 视口和内容测量均为 159×42；尚未验证可见浮窗在其他系统缩放下的表现。
- 管理员进程的 WebView2 会忽略环境变量调试参数；改用普通用户交互任务后，CDP 已连通。此为调试环境问题，不是裁切根因结论。

## 假设与边界

优先核对不同 DPI 屏幕之间的窗口、WebView 与内容尺寸同步，以及启动时异步恢复浮窗位置的顺序。用户 B 的恢复也可能与激活键变化引发内容重测有关；尚无证据证明这一解释适用于用户 A。

“先按动态内容设置窗口，再让内容适配实际视口”是候选修复方向；仅调整调用顺序不足以保证修复，需要核对动态宽度、实际可视区与跨屏 DPI 事件。

### 环境与覆盖

- 实机 Windows 构建 26300.9711、26H2，WebView2 156.0.4314.50，运行已安装 0.7.0 的临时副本，经 CDP 连接真实 WebView2；未重新构建产品。两屏均为 2560×1440，主屏原点 `(0, 0)`，左侧副屏原点 `(-2560, 0)`，原始缩放均为 100%。
- 测试副本先放 `%TEMP%`，被 Defender 行为检测终止；用户提供的排除目录覆盖 `D:\Workspace\flair-bloom`，改在该目录下运行后完成验证。进程被终止不计入裁切证据。
- 双屏 100%／100%、100%／125%、100%／150%、100%／200%、150%／150%；浮窗跨屏往返，面板保持另一屏的位置；内容覆盖空态，以及互斥组与单独激活键同时显示。应用缩放测试 1、1.25、1.5、2、2.3 倍；激活内容测试 1、1.5、2.3 倍。
- 上述矩阵共取得 119 个稳定后样本，未观察到超过 1 CSS 像素的内容越界；少量分数像素舍入不等同于用户录屏中的明显裁切。混合 DPI 下另做 4 次冷启动：面板横版 2.3 倍、恢复浮窗到 150% 副屏，显隐前后均未出现持续裁切。
- 原生测量示例：主屏 100%、副屏 125%，面板隐藏在主屏、浮窗可见于副屏。浮窗原生客户区、`WRY_WEBVIEW`、`Chrome_WidgetWin_1` 均为 199×53 物理像素、DPI 120；主面板三层均为 1072×603、DPI 96。

### 已复现：缩放切换中的短暂裁切

- 在 150% 副屏上，通过现有 `panel-scale-changed` 事件将应用 zoom 从 1 切为 2.3，4 轮逐帧采样均记录到 1 个裁切帧：内容约 158.71×41.73 CSS 像素，`innerWidth/innerHeight` 仅 69×18，DPR 3.45。之后自行恢复。
- 再用面板真实窗口尺寸变化触发原有缩放逻辑（未直接广播事件）：主屏 100%、浮窗在 125% 副屏，面板横版从 1072×603 调为 2466×1387。656 个动画帧样本中捕捉到连续 2 帧裁切：内容约 158.39×41.39、视口 69×18、DPR 2.875；首个异常采样后约 9.5 ms 已采到视口恢复为 159×41。操作使用窗口 API 设置尺寸，尚未用鼠标拖边复核。
- 这些读数支持“zoom 已变化、窗口尺寸尚未同步”的短暂时序窗口；不证明用户 A 的持续裁切同因。冷启动稳定样本、跨屏稳定样本均未卡在这一状态。

## 横版单屏反馈与只读采样

- 最新反馈：横版键盘左右两侧显示不全，单屏也能发生。固定宽度键盘居中、父容器 `overflow:hidden` 能解释两侧裁切的形态，但截图不能区分 WebView 实际 zoom 偏大、可用视口偏小、DPI 同步或布局尺寸问题。
- `useWindowScale.ts` 从窗口物理尺寸和 DPI 换算应用比例，只在 resize 路径调用 `setZoom`；保存的 `panelScale` 不能直接证明当前 WebView 实际 zoom。需要把原生窗口测量与实际 DOM 视口分开记录。
- 只读脚本：[scripts/diagnose-display-readonly.ps1](../../scripts/diagnose-display-readonly.ps1)。Windows PowerShell 5.1+，无需管理员；采集 Windows 构建、显示器尺寸／缩放、应用窗口与 WebView 子窗口客户区、DPI awareness、保存的布局／比例、WebView2 版本及应用 DPI 兼容标志。只写诊断 JSON，不调整应用、系统缩放或驱动；测量用的线程 DPI 上下文仅影响脚本自身且会恢复。不读取配置名称、规则、许可证或日志正文。
- 在裁切发生、窗口可见时运行脚本，默认在桌面生成 `flair-display-*.json`。脚本不打开调试端口，**没有读取页面 `innerWidth`、DPR 或实际 ZoomFactor**；普通权限无法取得的进程版本可能为 null，不能据此认为 WebView2 未安装。
- 本机默认横版对照：作者切换为横版默认大小后采集，保存布局为 horizontal、横竖比例均为 1、未最大化；主面板、`WRY_WEBVIEW`、`Chrome_WidgetWin_1` 均为 1072×603 物理像素、DPI 96。两屏均 2560×1440、100%；正在使用 WebView2 156.0.4314.50。采集无错误；这确认原生尺寸链路一致，不代表已证明实际页面 zoom 为 1。
